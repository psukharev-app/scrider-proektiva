# Отчет по управлению проектом «Scrider»: Этап завершения

---

## 1. Достигнутые результаты

Проект завершен с превышением плановых показателей:

| Показатель | План | Факт |
| :--- | :---: | :---: |
| Поддержка LaTeX-команд | 50 | 67 |
| Время ответа (50 страниц) | <100 мс | 87 мс |
| npm-установки | 1 000 | 1 247 |
| Покрытие кода тестами | >80% | 84% |
| Удовлетворенность пользователей (SUS) | >70 | 78 |

**Ключевые артефакты:**
- Рабочий MVP: https://proektiva-scrider.infra-net.pro/
- npm-пакеты: @scrider/editor-core, @scrider/editor-react
- Полный комплект документации (API, руководство, архитектура)

---

## 2. Используемые технологии

| Слой | Технологии |
| :--- | :--- |
| **Core** | TypeScript, Delta (OT), @scrider/formatter |
| **UI** | React 18, Slate.js, CSS Custom Properties |
| **Рендеринг** | Katex (формулы), Prism.js (код), MathJax (PDF) |
| **Сборка/CI** | tsup, GitHub Actions, pnpm |
| **Инфраструктура** | Yandex Cloud (демо), GitHub (код), Jira (задачи) |

## 4. Негативные факторы и их влияние

| Фактор | Влияние | Перерасход |
| :--- | :---: | :---: |
| Сложность рендеринга LaTeX | Высокое | +2 дня |
| Реализация rowspan/colspan | Высокое | +3 дня |
| Экспорт PDF с формулами | Среднее | +2 дня |
| Изменение требований от ученых | Среднее | +1 день |

**Итоговое отклонение:** +3 дня (в пределах буфера)

---

## 5. Рекомендации по избеганию негативных факторов

| Фактор | Рекомендация |
| :--- | :--- |
| Сложность LaTeX | Выделять исследовательский спринт до начала MVP |
| Сложные таблицы | Закладывать буфер +5 дней, исследовать готовые решения |
| Изменение требований | Ввести Change Request Board, заморозить требования к спринту |
| Документирование | Выделять 10% времени спринта, использовать автогенерацию (TypeDoc) |
| Совмещение ролей | В высокотемповых проектах не совмещать PM и DevOps |

---

## 6. Предпринятые меры по минимизации рисков

| Риск | Мера | Результат |
| :--- | :--- | :--- |
| Сложность формул | Ограничение MVP 50 командами, Katex | +2 дня (принято) |
| Сложность таблиц | Отдельный спринт, кастомная модель | +3 дня (принято) |
| Производительность | Нагрузочное тестирование в каждом спринте | 87 мс (<100 мс) |
| Зависимость от CDN | Lazy-load MathJax, локальные кеши | Без сбоев |
| Санкционные риски | Резервный план (Verdaccio, GitLab) | Не потребовался |

---

## 7. Идеи по улучшению процесса управления

| Область | Идея |
| :--- | :--- |
| **Планирование** | Закладывать исследовательские спринты для технически сложных задач (LaTeX, таблицы) |
| **Управление требованиями** | Ввести формальную процедуру Change Request Board с оценкой влияния на сроки |
| **Документирование** | Внедрить автогенерацию документации (TypeDoc, JSDoc) и выделять время на обновление в каждом спринте |
| **Контроль качества** | Автоматизировать регрессионное тестирование через GitHub Actions (запуск при каждом PR) |
| **Команда** | В проектах с высокой технической сложностью не совмещать ключевые роли (PM и DevOps) |
| **Риски** | Создать матрицу рисков с триггерами для раннего срабатывания (например, «если исследование LaTeX >3 дней — сократить объем») |
| **Коммуникация** | Внедрить еженедельные демо для стейкхолдеров (вместо ежемесячных) для более ранней обратной связи |

---

## Заключение

Проект «Scrider» завершен успешно: все плановые показатели достигнуты или превышены, создан работающий MVP, опубликованы npm-пакеты, привлечены первые пользователи. Основные сложности были связаны с технической реализацией LaTeX-формул и сложных таблиц, что привело к перерасходу +8 дней, компенсированному за счет буферов (итоговое отклонение +3 дня). Ключевыми факторами успеха стали квалификация команды, четкая архитектура, гибридная методология и раннее привлечение пользователей. Предложенные улучшения (исследовательские спринты, автоматизация документации, разделение ключевых ролей) позволят повысить эффективность будущих проектов.
