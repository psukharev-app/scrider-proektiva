# Идеология подхода Scrider

## Суть подхода

Scrider строится как редактор, где модель данных и архитектурные контракты важнее конкретного UI-стека. Интерфейс может меняться, но поведение системы должно оставаться согласованным и проверяемым.

## Основные принципы

- **Data-first:** источник истины — структура контента и состояние редактора, а не DOM.
- **Framework-agnostic core:** ключевая логика живет в независимом ядре и не привязана к конкретному фреймворку.
- **Тонкие обертки:** UI-слой отвечает за интеграцию с платформой (`React`, `contentEditable`, события), а не за бизнес-логику.
- **Расширяемость по контрактам:** новые возможности подключаются через registry/plugin-механизмы без разрушения базовой архитектуры.
- **Тестируемость по умолчанию:** проверяемость закладывается в дизайн решений на уровне core и интеграционного слоя.

## Практический вектор

Подход Scrider направлен на:

- предсказуемое развитие функциональности;
- переносимость между UI-стеками;
- снижение технического долга при добавлении форматов, плагинов и сценариев экспорта;
- прозрачную связь требований, реализации и проверок.

## Идеологический критерий качества

Любое архитектурное решение считается хорошим, если оно одновременно:

- не увеличивает связанность ядра с платформой;
- сохраняет детерминированность поведения;
- улучшает расширяемость;
- остается проверяемым через тесты и воспроизводимые сценарии.
